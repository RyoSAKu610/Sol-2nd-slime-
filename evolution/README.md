# DEAP で数値条件を探す

GA は、流動性下限・5分出来高下限・スコア下限・利確率・損切率の **5条件** を試して比較します。AI全体の能力が自己進化する仕組みではありません。常駐監視とは独立した、記録済みデータを読む実験です。常駐設定や資金を変更しません。

```sh
python3 -m venv evolution/.venv
evolution/.venv/bin/python -m pip install -r evolution/requirements.txt
evolution/.venv/bin/python -m evolution run
```

通常の監視を動かすために DEAP を入れる必要はありません。データ不足の確認は `python3 -m evolution run` だけでも動きます。実データは既定で `~/Library/Application Support/SecondaryBrainRadar/radar.sqlite3` を読み取り専用で使用します。Nansenキー・ウォレット・認証情報は読み込みません。設定ファイルのキー参照/ウォレット項目もレポートから除外します。

合成データで機械的な動作を確認するコマンド:

```sh
evolution/.venv/bin/python -m evolution demo
evolution/.venv/bin/python -m unittest discover -s tests -p test_evolution.py -v
```

結果は `evolution/runs/observed/<実験ID>/report.md` と `report.json` に保存します。デモは必ず `runs/demo/` に隔離し、実績として扱いません。同じデータ・設定・コードでの再実行は既存レポートを返します。異なる実験で評価期間が重なった場合は「新しい未使用期間ではない」と記録します。

同じ出力先への同時起動はプロセス間ロックで順番に処理し、待機後に既存結果を確認します。同一実験の重複探索を防ぎ、完成したレポートだけを置き換えます。このロックはmacOS/Linux向けです。

## 何を検証するか

- 仮説: 一定の流動性と取引活動がある銘柄で条件を変更すると、費用控除後のpaper結果が固定条件より改善する可能性がある。
- データ: 内容ハッシュで不変性を確認したDex観測の **初回取得時刻** のみ。最新の再取得時刻・現在のtoken表・後日変更されるNansen情報を過去に流用しません。上場前や監視開始前の履歴を作りません。
- 学習: 時間の前70%だけで DEAP `eaSimple` を実行。16個体×4世代、固定seed、同じ遺伝子は再計算しません。探索範囲はコードに固定され、holdoutでは再探索しません。
- 評価: 残り30%を、固定の現在設定・現金保有と比較します。各側を3個の連続区間に分け、毎区間20ドルから開始。建玉・待機注文・価格キャッシュは区間を跨ぎません。区間平均と標準偏差は記述値であり、有意差の証明ではありません。
- データの最低条件: 7日・3銘柄・各区間50観測・各区間が最大保有時間より長いこと。学習の決済が5件未満の候補は失格。この最低条件を満たしても実用性や統計的確証は保証しません。
- 費用: 既定は片道1% slippage・0.3%手数料・0.002ドルネットワーク費。注文2ドル、留保10ドル、最大3建玉、同一銘柄再入場24時間。手数料・スコア・資金規則は常駐と揃え、買いは検出後の次の観測でのみ模擬します。
- 指標: 現金リターン下限平均から最大下落率の0.5倍を減点。未決済/消滅/欠測資産の下限評価は0ドルです。参考時価と未決済数を別に残し、売れたと仮定しません。利益や実際の約定を保証する指標ではありません。

学習区間の欠損率・四分位・外れ値・流動性と出来高の相関・観測間の価格変化方向を記録します。相関を因果とみなさず、これらからholdoutを見て探索範囲を変更しません。データhash、コードhash、seed、条件、試行数、期間、費用、件数、下落率、baseline差もJSONに残ります。自動設定反映や学習結果の自動メモリー登録はありません。

## 計算量と入力制限

既定は最新の初回観測から28日、最大100,000行。入力超過は先頭だけで評価せず `insufficient_data` にします。`--window-days`（7〜365）、`--max-observations`（1〜1,000,000）、`--population`（4〜128）、`--generations`（1〜100）で明示変更できます。最大推定点評価は10,000,000を上限にし、超える実験は走らせません。入力の件数上限はメモリーへの読み込みを制限します。DB側で期間を検索する時間は蓄積量に依存します。

N=価格点数、U=異なる遺伝子の実評価数、A=同時刻の銘柄数として、読込/並べ替えは時間O(N log N)、探索は概ねO(U × N log A)、空間は観測O(N)と評価結果O(U × 取引件数)。スコア関数を将来変更したら、再現hashが変わるため別実験になります。リファクタリング余地は、十分な履歴が集まった後の区間別前処理共有・評価キャッシュの圧縮です。

## 残る失敗候補

1. **選択/生存者バイアスと過学習:** 発見済み銘柄だけで最適化すると、未発見銘柄や将来の相場で機能しない可能性があります。同じholdoutを繰り返し眺めることも過学習に繋がります。これは実証した利益/欠陥ではなく、実運用前に検証するリスクです。
2. **欠測と売却不能:** 同一内容の再観測を重複排除しているため、全ポーリング時刻の価格列は復元できません。DEXの取得時刻は価格の更新時刻ではなく、流動性の見かけが十分でも実際に売れない可能性があります。最新価格による穴埋めは行いません。

推奨される次の段階は、まず将来の観測期間を蓄積し、固定した候補を新しい期間で比較することです。20ドルから年末1,000万ドルへの到達をこの実験で予測・保証しません。

公式資料: [DEAP概要](https://deap.readthedocs.io/en/master/overview.html)、[eaSimpleと変異アルゴリズム](https://deap.readthedocs.io/en/master/api/algo.html)。
